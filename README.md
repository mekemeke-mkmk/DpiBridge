# DpiBridge

解像度・拡大率が大きく違うモニター間（例: Sunshine + 仮想ディスプレイで配信している Surface と、普通の物理モニター）でウィンドウを動かしたとき、
**見た目の大きさ（実寸 mm）が揃うように自動でサイズを補正する** Windows 常駐アプリです。
他のプロセスへの DLL 注入はせず、Windows 標準の仕組み（WinEvent フック + SetWindowPos）だけで動きます。

機能: 診断画面 / モニター間移動時の自動サイズ補正 / 見た目キャリブレーション / 自動更新。

## インストール
1. [.NET 8 デスクトップ ランタイム](https://dotnet.microsoft.com/download/dotnet/8.0)（「.NET Desktop Runtime 8.x」x64）を入れる。
2. [Releases](https://github.com/mekemeke-mkmk/DpiBridge/releases/latest) から `DpiBridge.exe` をダウンロードし、
   **書き込みできるフォルダー**（例: `ドキュメント\DpiBridge`）に置いて起動する。
   `Program Files` などに置くと自動更新できません。
3. トレイアイコンの右クリック →「Windows のサインイン時に起動」にチェックすると、毎回自動で起動します。

## 更新
- 起動時と 12 時間ごとに新しいバージョンを自動で確認し、見つかると通知が出ます。**通知をクリック → 「はい」で更新完了**です
  （数秒で再起動し、設定はそのまま引き継がれます）。
- トレイメニューの「更新を確認...」でいつでも確認できます。
- 「更新を自動でインストール」にチェックすると、確認なしで自動更新します。
- ダウンロードした exe は SHA-256 で検証してから置き換えます。失敗した場合は元のバージョンのまま動き続けます。

## 動作環境
- Windows 10 / 11 (x64) + .NET 8 デスクトップ ランタイム

## 使い方
1. `DpiBridge.exe` を起動するとタスクトレイに常駐し、診断と設定の画面が開きます。
2. **「見た目キャリブレーション...」を押します**（トレイアイコンの右クリックメニューからも実行できます）。
   - すべてのモニターに全画面の調整画面が出ます。各モニターで、青い枠が **実物の IC カード／クレジットカード（85.6×54mm）** と
     同じ大きさになるよう調整します（定規があるなら黄色い線を 10cm に）。
   - マウスホイール／← → キーで調整（Shift: 微調整、Ctrl: 粗調整）、**Enter で全モニターを保存**、Esc でキャンセル。
   - Windows の拡大率、解像度、Moonlight による引き伸ばしをすべて含めた「実際に目に見える大きさ」を実測するので、
     **両方のモニターが同じ拡大率（例: 100%）でも見た目が揃うように補正されます。**
   - 仮想ディスプレイ（Surface 側）は実際の見た目の大きさを Windows から取得できないため、この操作が必須です。
3. あとはふだん通りウィンドウをドラッグしてモニター間を移動するだけです。
   離した直後に、移動前と同じ見た目の大きさへ滑らかに補正されます。
4. **補正履歴** タブで、補正した内容と **補正しなかった理由**（最大化中・スナップ配置中・既に適切な大きさ など）を確認できます。
   うまく動かないときはまずここを見てください。
5. **ウィンドウ診断** タブを開いたまま、気になるウィンドウ（タスクマネージャー等）にマウスを乗せると、
   DPI 対応状況とぼやけの原因・対処法を表示します。

### なめらかなドラッグ（0.4.0〜）
タイトルバーをドラッグすると、見た目の違うモニターにかかる間は DpiBridge がウィンドウのプレビューを
各モニターの実際の大きさで描いてつなげます。途中で大きさが跳ねたり、一部だけ大きく見えたりしません。
離すと移動先でちょうどよい大きさに 1 回で配置されます。
- Shift を押しながらドラッグ: Windows 標準のドラッグ（スナップレイアウト等）
- ドラッグ中に Esc: 取り消し
- 画面外周の端で離す: 上端=最大化、左右端=半分
- 管理者権限で動くアプリ（タスクマネージャー等）は、DpiBridge も管理者として実行しているときだけ対象になります。
- トレイメニューの「モニター間をなめらかにドラッグ」で無効にできます。

### 拡大率について
DpiBridge が揃えるのは **ウィンドウの外枠の大きさ** です。ウィンドウの中の文字の大きさは Windows の拡大率で決まります。
キャリブレーション後、モニタータブの「診断結果」に、文字の大きさも揃えるための推奨拡大率が表示されます。
推奨どおりに拡大率を変えると、ドラッグ中のサイズの跳ねも小さくなります（変えなくても外枠は揃います）。

### 管理者権限で動くアプリ（タスクマネージャー等）
Windows の仕様（UIPI）で、通常権限のアプリは管理者権限のウィンドウを動かせません。
タスクマネージャーも補正したい場合は `DpiBridge.exe` を右クリック →「管理者として実行」してください。
（自動起動の設定は Phase 3 で追加予定です。）

### 設定ファイル
`%AppData%\DpiBridge\settings.json`。アプリごとの補正方法は今のところ手で編集します:
```json
"AppModes": {
  "someapp.exe": "None",
  "otherapp.exe": "WorkAreaRatio"
}
```
`PhysicalSize`（実寸維持・既定）/ `WorkAreaRatio`（画面比率維持）/ `None`（補正しない）。
ログは `%AppData%\DpiBridge\dpibridge.log`。

## ぼやけ対策の考え方
| 原因 | 見分け方（ウィンドウ診断タブ） | 対処 |
|---|---|---|
| 配信解像度の不一致（仮想ディスプレイ/Sunshine/Moonlight の解像度が Surface 本来の解像度と違う） | PMv2 対応アプリなのにぼやける / モニタータブで「問題」表示 | 仮想ディスプレイ・Sunshine・Moonlight の解像度をすべて Surface のネイティブ解像度に揃える |
| アプリが DPI 非対応 / System DPI | 「非対応」「System」と表示 | exe のプロパティ → 互換性 → 高 DPI 設定の変更 →「アプリケーション」か「システム (拡張)」 |

## 既知の制限（今後のフェーズで対応）
- ドラッグ中に DPI が切り替わる瞬間の一時的な拡大は Windows 自身の動作のため残ります。
  → Phase 2 でショートカットキーによる「一発移動」（中間状態を経由しない）を追加予定。
- 最大化・スナップ配置・サイズ変更不可のウィンドウは補正しません（意図的）。

## リリースの作り方（開発者向け）
`src/DpiBridge.App/DpiBridge.App.csproj` の `<Version>` を上げ、`CHANGELOG.md` に同じ番号の節を書いて main に push するだけです。
GitHub Actions（`.github/workflows/release.yml`）がテスト・ビルドして `v{Version}` の Release を作り、
インストール済みの DpiBridge が自動で検出して更新します。

## ビルド
```bash
dotnet test tests/DpiBridge.Core.Tests
dotnet publish src/DpiBridge.App -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o publish
```
Linux 上でもビルドできるよう、WindowsDesktop SDK ではなく `FrameworkReference` で WinForms を参照しています。

## 構成
- `src/DpiBridge.Core` — OS に依存しないロジック（サイズ計算・EDID 解析・診断・設定）。単体テスト対象。
- `src/DpiBridge.App` — Win32 連携（モニター列挙、WinEvent 監視、ウィンドウ移動）とトレイ/診断 UI。
- `tests/DpiBridge.Core.Tests` — xUnit テスト。
